# 装填（ST3215）の制御 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PC の `load` モード（L1 / ○）で ST3215 をステップモードで 1 セルずつ回す。端数を溜めず、押下を取りこぼさず、途絶で止まる。

**Architecture:** rabcl `Feeder`（モード × 時刻 → 今送るステップ数。実数累積の round 差分）をホストでテストし、gamma_turret_fw の `FeederTask`（専用 FreeRTOS タスク）が `Controller::load_mode()` を読んで `St3215::Move` を送る。

**Tech Stack:** rabcl（ament_cmake + gtest、ws_dev で `colcon build --packages-select rabcl && colcon test`）、ESP-IDF 5.5、PlatformIO。

**Spec:** `docs/superpowers/specs/2026-11-16-feeder-design.md`

## Global Constraints

- rabcl に機体の値を置かない（カウント / セル、周期は `FeederConfig` で渡す）。rabcl の変更はユニットテスト必須。
- ファームは EEPROM（MODE、角度制限）を書かない。確認だけ。
- 定数は UPPER_SNAKE_CASE。外部ヘッダは `<>`、自リポジトリは `""`。
- コミットはユーザー承認後。ファームは実機確認後。

## Review Focus

- `Update` が period 未満の間に FORWARD → STOP → FORWARD と来たとき、2 発目は period 経過時に 1 回だけ（保留は 1 つ）。
- FORWARD → REVERSE の直接切り替え: 保留の向きは新しいモード。
- 逆転で `target` が負になっても `lround` の差分が正しい（−170.67 → −171、−341.33 → −341 → 差 −170）。
- `Cancel` 後に STOP が続けば何も出ない。`Cancel` 後に FORWARD の新しいエッジは普通に出る。
- `FeederTask`: サーボ電源断（Ping 失敗 / Move 失敗が `FEED_FAIL_LIMIT`）→ NOT_READY → 復電で READY。その間 `Feeder` のモードは STOP 扱いで保留は捨てる。
