# 射出 ESC の PWM 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** rabcl_esp32 に LEDC を包む `PwmOut` を足し、gamma_turret_fw が `fire` モードで ESC 2 本に 1000 / 1200 µs の 50 Hz パルスを出す。

**Architecture:** `PwmOut` は ESP-IDF の `ledc_*` を包むだけ（ホスト側 fake でテスト）。パルス幅は `Controller::Tick` が決めて `fire_pulse_us()` で返し、`main.cpp` の制御タスクが 2 本の `PwmOut` に書く。起動直後から 1000 µs、校正シーケンスは無し。

**Tech Stack:** ESP-IDF 5.5（esp_driver_ledc）、gtest（rabcl_esp32 のホストテスト。ws_dev コンテナへ `docker cp` して cmake）、PlatformIO（pioarduino）。

**Spec:** `docs/superpowers/specs/2026-11-16-esc-pwm-design.md`

## Global Constraints

- 通常ファームが出すパルス幅は `FIRE_PULSE_MAX_US`（1800 µs）以下（`static_assert`）。
- `PwmOut` のコンストラクタはハードを触らない。`Start()` で初期化し `esp_err_t` を返す。
- 機体固有の値（ピン、周波数、パルス幅）は rabcl_esp32 に置かず、`board.hpp` / `robot.hpp` に置く。
- C++: 定数は UPPER_SNAKE_CASE、外部ヘッダは `<>`、自リポジトリは `""`。
- コミットはユーザーの承認後（ステージして見せる）。ファームのコミットは実機確認後。

## Review Focus

- `SetPulseUs(0)`: duty 0 = Low のまま。ESC は信号無しと同じ扱い（アーミング解除）。
- `SetPulseUs(周期と同じ 20000)`: duty = 2^res（ESP-IDF は `[0, 2^res]` を許す）。それを超える幅は `ESP_ERR_INVALID_ARG`。
- `Start()` 2 回目: `ESP_ERR_INVALID_STATE`、ハードを再設定しない。
- 途絶中に `fire = 1` が残っていても 1000 µs。
- 2 本目の `Start()` が同じタイマーを再設定しても 1 本目のパルスが変わらない（同じ周波数 / 分解能）。
